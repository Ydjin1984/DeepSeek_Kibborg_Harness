# Agent Note：会话活动记录与读者控制的跟随

Status: implemented

[English](2026-09-19-conversation-activity-follow-and-code.md) | 中文

## 问题

会话执行记录在每个动作周围重复标签与边框，长历史又挂载过多行。聊天与轨迹在读者检查较早内容时仍可能移动视口，输入框也无法区分用户编写的代码围栏与引用或命令。折叠动作中的文件路径不能稳定地展示已记录的预览。

## 决策

执行视图只在已记录的轮次或步骤起点对现有 Chat 节点分组。编号轮次标题与默认折叠的动作行避免重复显示用户和助手文本；文件路径有独立的键盘按钮，可展开已记录的读取或差异卡片。带实测高度的虚拟窗口保留稳定节点键，展开内容仍交给现有工具渲染器。聊天与执行视图从已加载的用户请求和中途引导节点生成数量受限的请求刻度。同一纯函数跟随状态机处理读者主动离开、手动回到底部、跳转进行中及跳转中断。各视图自行管理 DOM 滚动，并在已挂载的 Session 壳中保存临时阅读锚点；轨迹在向前补页时使用虚拟行键与偏移量。流式内容增高时仅在跟随状态每帧至多写入一次，跳转遵循减少动态效果设置。

会话初次请求只保留数量受限的末尾窗口。执行视图提供与聊天视图相同的历史补页操作；只要较早事件仍在窗口之外，请求刻度栏就显示加载控制，即使当前没有已加载的请求。刻度只从已加载的用户请求和中途引导节点生成，界面不会暗示已索引隐藏的历史。

用户编写的三个反引号代码围栏按 UTF-16 偏移切分，不修改提交文本。原生 textarea 继续管理选区和光标；对齐底层高亮代码，发送后的用户消息沿用现有 CodeBlock。围栏中的引用和命令触发字符保持普通文本。未闭合围栏覆盖草稿余下部分。

消息代码围栏的复制横幅按正常文档流放在代码正文前；页面滚动后，原来的 sticky 横幅会在短代码块底部受到约束。已定稿的助手围栏和已发送的用户围栏显示行号，并为声明的语言高亮。未标注语言的围栏只保守识别常见源码语法；示意图保持纯文本，流式回复延至定稿才进行高亮。

纯函数状态机与扫描器位于 ui-primitives；客户端模块表已向两个 UI 插件共享它。这样无需让 conversation、trajectory 或 input-trigger 插件相互导入运行时值。会话事件和模型请求格式不变。

## 曾考虑的替代方案

**始终追随底部的单个滚动监听器。** 否决：程序化布局更新与读者手势表达不同意图，会在阅读时夺走视口。

**为全部执行历史挂载完整列表。** 否决：展开的工具卡片开销较高，DOM 会随事件数量增长；实测虚拟化仅保留可见卡片。

**按文件名重新构造预览。** 否决：已记录的工具卡片持有准确行号、语言、差异和错误。路径只是通向证据的导航，不能凭空生成内容。

**自定义富文本输入框。** 否决：原生 textarea 已管理输入法、光标、选区与无障碍编辑；底层可增加视觉区分而不替换编辑语义。

## 后果

读者决定何时持续看到最新动作。请求刻度只指向已加载历史，切换标签页会在当前会话中保留阅读位置。紧凑记录行无需挂载所有详情卡片也能阅读。UI 原子包增加两个供多个插件共享的纯函数；呈现状态保持临时，不增加持久日志流量。

## 测试

客户端定向测试覆盖分组、代码围栏、引用识别、文件展开、请求导航、执行行挂载上限、跟随状态转换、向上移动一个像素、流式内容增高和虚拟行书签恢复。无密钥组装态 fixture [conversation-feed.snapshot.ts](../../../../apps/web/tests/conversation-feed.snapshot.ts) 和 [user-code-fences.snapshot.ts](../../../../apps/web/tests/user-code-fences.snapshot.ts) 通过已构建的插件包固定分组动作、已记录的读取卡片，以及实际发送的代码草稿。浏览器几何、导航和现有性能证据记录在 [conversation-activity.baseline.md](../../../../apps/web/tests/conversation-activity.baseline.md)。

现有的长历史浏览器基准测试依赖会话数量标签和全部挂载的侧边栏。面对当前虚拟化侧边栏时，它在记录执行日志耗时之前停止；执行视图的 DOM 数量上限测试仅证明挂载数量，不证明帧耗时或内存目标。
