# @deepseek-ai/dsh-client-ui-files

[English](README.md) | 中文

工作区文件面板（浏览器半区）：输入工具栏（`conversation.input.left`，回形针按钮所在的列表位）中的一个 occupant，可在当前会话项目文件夹之上打开右侧抽屉。抽屉展示项目的文件树——文件夹通过 `host.listChildren` 惰性展开，隐藏（点前缀）文件会被列出但弱化显示——文件行可拖拽到输入框。放下时通过 `host.readTextFile` 读取文件，并作为普通文件草稿（`inputActions.addFiles`）附加，因此宿主对 OS 拖放已有的准入路径会原样把内容物化进模型上下文。

双击文件会打开内置 Markdown 查看/编辑对话框：预览复用共享的 `MarkdownText` 渲染器，编辑使用普通 textarea，保存通过 `host.writeTextFile` 写回。预览与编辑共享同一份草稿，脏关闭会先询问是否放弃。

三个宿主动词都按会话路由，并由宿主做包含性校验（`api-proxy` 解析会话记录的 project cwd，拒绝任何越界路径），因此面板无法浏览或编辑用户打开的项目之外的内容。Node 半区为空；注册、词典与 occupant 都在浏览器半区。

## 模型体验

间接影响：拖入的文件会成为普通草稿文件——提交时宿主解码并将其文本折叠进持久用户消息，与用户用回形针选择完全一致。通过对话框编辑 Markdown 文件会直接写盘；两者本身都不增加提示内容。

#### KV Cache 影响

无。面板不发起模型调用；被折叠进消息的内容走常规提示路径。

## 已知限制与延后工作

- **仅文本附加** —— 文件抽屉读取 UTF-8 文本（`host.readTextFile`）；二进制拖放会以内联错误提示而非附加字节。
- **以会话为根** —— 树根固定为当前会话的项目文件夹；暂不提供浏览其它文件夹。
- **编辑器范围** —— 对话框是单文件纯 textarea 编辑器；暂无多文件标签或富编辑计划。
- **拖放附加的是副本** —— 从树中拖入的文件走普通草稿管线：宿主把字节物化到 `.dsh/attachments`，并向模型描述该副本（`Attached file: …/Path: …`）。模型可见文本中暂不引用该行在项目中的原始路径；按引用附加已延后，直到提示部件（prompt part）的线上字段携带原始路径。
