# @deepseek-ai/dsh-client-ui-settings-claude-code

Claude Code technology settings section: manages the ECC-derived skill library
(`.dsh/skills` `cc-*` and `cc-role-*` skills converted from
[affaan-m/ECC](https://github.com/affaan-m/ECC), Everything Claude Code v2.2.1).

The section enables and disables library skills through the skill-manager RPC
domain (`skills.listManaged` / `skills.setEnabled`, one call per skill) and
explains the chat invocation. Enabling a skill removes its `.disabled` marker;
the skill-filesystem watcher then publishes it to the agent skill catalog on
the next turn, where the model can load it by name.

## Model Experience

- **Prompt catalog effect**: every enabled library skill appends one
  `available_skills` entry (base `description`, truncated to 500 chars) to the
  model prompt. The recommended default keeps ~55 skills enabled; the bulk
  controls can raise that to all ~355, which increases prompt size by roughly
  one description per skill — the user's explicit choice.
- **The `claude-code` umbrella skill** stays enabled so the activation phrase
  ("use the Claude Code technology" and variants) resolves in every session.
- **No KV-cache or per-request token effect** beyond the catalog entry lines.

## Settings section

Registered into the `settings.section` slot:

| field | value |
| --- | --- |
| id | `claude-code` |
| order | 18 |
| locale namespace | `settings.claudeCode` |

Controls:

- Recommended set (enable), Enable all, Disable all — bulk sequential
  `setEnabled` calls over the generated `groups.data.ts` name lists;
  the umbrella skill is never touched by bulk toggles.
- One row per category (TDD & testing, review, security, agentic, …) with a
  tri-state checkbox reflecting how many members are enabled.

## Generated data

`src/client/groups.data.ts` (categories, recommended set) is generated by
`.planning/phases/claude-code/gen-groups.mjs` from the library on disk — edit
the generator, not the data file. The library itself is produced by
`.planning/phases/claude-code/convert-ecc.mjs` from an ECC clone.

## Known Limitations and Deferred Work

- Category membership is a keyword heuristic over skill names; niche skills
  may land in "Everything else". Use the Skills Manager section for precise
  per-skill toggles.
- Bulk toggles are one `setEnabled` RPC per skill (no batch API); enabling all
  ~355 skills takes a few seconds of sequential calls.
- Converted skills carry only their `SKILL.md` body: ECC skills whose text
  references companion files (`references/`, `examples/`, `scripts/`) lose
  those assets and work from their inline instructions alone.
- Discovery re-parses every library `SKILL.md` per agent step: with ~355
  disabled members the catalog scan costs tens of milliseconds; enable only the
  categories you use, or disable the whole library from this section.
