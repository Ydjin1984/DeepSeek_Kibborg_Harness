## 2. Что за проект (одним абзацем)

**DeepSeek_Kibborg_Harness** — это модифицированный форк **DeepSeek Harness** (`dsh`,
v`0.1.0-rc.8`, лицензия MIT) — открытого агент-харнесса от DeepSeek AI, построенного по принципу
**«всё — плагин»** на вендоренном фреймворке Cordis. Мы добавили в него персональный слой:
режим **оркестратора** (головная модель + исполнитель с vision), развитую **систему скиллов**
(каталог, менеджер, бенчмарки, авто-улучшение), веб-GUI, а также инструментарий для
**кибербезопасности, пентеста, реверс-инжиниринга** и других специализированных задач.

Целевое видение: **«супер-турбо среда»** для лайв-кодинга, хакинга / авторизованного пентеста,
реверс-инжиниринга и всего остального — одна платформа, где человек управляет оркестром
ИИ-агентов (включая внешние модели-консультантов), а агенты умеют работать с кодом, файлами,
браузером, терминалом, сетью и инструментами безопасности.

## 3. Технологический стек

- **Монорепозиторий**: pnpm workspaces (`pnpm@11.7.0`), Node `^22.19 || >=24`, ESM, TypeScript `strict`.
- **Ядро**: вендоренный Cordis (паттерны «Service Definition / Provider / Consumer», эффекты через
  `ctx.effect()`, водопадные listeners, типизированные события с declaration merging).
- **Пакеты**: `@deepseek-ai/dsh-<name>`; ~50 групп пакетов в `packages/<group>/<pkg>/`.
- **Веб-GUI**: React + Vite, хост на `http://127.0.0.1:3080`, клиентская половина `apps/web`,
  серверная — `packages/host` + RPC-шлюз Typert; 50+ Playwright snapshot-тестов GUI.
- **Сессии**: durable-формат JSONL + SQLite (монотонный `SCHEMA_VERSION`), проекции, телеметрия,
  «модель-видимое ⟺ логируемое».
- **Тесты**: Vitest (unit, 100% coverage-гейт на пакетах), snapshot-тесты, e2e (реальные API,
  self-skip без `DEEPSEEK_API_KEY`), stress-тесты Web GUI.
- **Песочницы/процессы**: локальный провайдер shell/pwsh, subprocess с деревом процессов,
  Landlock (native), E2B POC.
- **LLM**: DeepSeek-провайдеры; в работе несколько моделей (голова `deepseek-v4-flash`,
  исполнитель `Kibborg_Flash_v5.7` и др.).

Ключевые инварианты архитектуры: «регистрации — это эффекты»; «модель-видимое ⟺ логируемое»
(всё, что уходит в модель, восстанавливается из лога сессии); капабилити-шов всегда полный
(Service Definition + Provider + Consumer); изменения agent-loop только через задокументированные
extension points (docs/architecture.md).

## 5. Ключевые механики платформы

### 5.1 Оркестратор «голова + исполнитель» (наша ключевая доработка)
- **Головная модель** (планирующая, `deepseek-v4-flash`) — думает дёшево, планирует, делегирует,
  проверяет результаты; зрения не имеет.
- **Исполнитель** (`Kibborg_Flash_v5.7`, локальный) — выполняет тяжёлую инструментальную работу
  одним заданием, возвращает сжатый отчёт; **имеет vision** (читает скриншоты, GUI, картинки).
- Правила: тяжёлые цепочки инструментов не выполняет голова; исполнитель получает самодостаточные
  задания; визуальный осмотр только через скриншот Chrome + чтение исполнителем.

### 5.2 Веб-браузер Chrome (CDP) как инструмент агента
- Chrome в dev-режиме, DevTools Protocol на `127.0.0.1:9222`, управление через CDP-клиент
  (`node ...\cdp.mjs ensure|open|text|html|eval|click|shot|close`).
- «Живой текст» тянется прямо из DOM (`text`/`eval`), скриншоты — только для визуального осмотра.

### 5.3 Система скиллов (реализована по ТЗ на 100%)
- Skill Manager: CRUD, конфликт-резолюция, корзина/restore, версии + rollback, publish.
- Benchmark engine: A/B-тесты, evaluator, метрики, Auto Improve (итеративное улучшение скилла).
- RPC-домен `skills` расширен методами менеджера; UI — вкладка Skills в настройках (карточки, поиск).
- 97 jsdom-тестов, 100% unit-покрытие; ТЗ на ~2030 строк: `ТЗ_ Skill Creator + Skills Manager +
  Benchmark для DeepSeek Harness.md`.

### 5.4 Специализированные скиллы (пользовательский профиль)
- `hakker-kibborg` — авторизованный red-team / пентест (scope, attack-path, evidence-driven).
- `ida-professional` — управление локальной IDA Pro 9.2 (idat headless, IDAPython, Hex-Rays).
- `reverse-engineering` — полный пайплайн реверса бинарников (PE/ELF/Mach-O/APK/firmware).
- `tor-web-search` — OSINT через локальный Tor (onion-поисковики, легальные границы).
- `tunerpro-xdf-engineer` — работа с TunerPro BIN/XDF/ADX.
- Плюс 9 служебных `dsh-*` скиллов (код-ревью, доки, стиль, pre-push и т.д.) в `.agents/skills`
  и системные скиллы (cc-*, design-*, orchestrator-* и др.) в каталоге сессии.

### 5.5 Агентный инструментарий
- Субагенты (background по умолчанию, durable id, fork с наследованием контекста), workflow-скрипты
  (фазы, pipeline, parallel), goal-циклы с авто-продолжением, фоновые jobs, Ralph-циклы.
- Тулы: todo, subagent, workflow, goal, job_*, skill/skill_manage, web_search, Chrome CDP,
  fs-тулы (read/write/edit/glob/grep), pwsh (в т.ч. фоновые), plan mode, ask-user, executor.

### 5.6 Веб-GUI и инфраструктура запуска
- Web GUI: чат, файловые панели, скилы, настройки; хост `127.0.0.1:3080`.
- `run.bat` + `progress.ps1` — сборка/запуск с прогресс-баром; веб-лог ротация.
- Кастомные панели/мониторинг: вкладка меню «живой мониторинг», PM·DASH (Polymarket terminal на
  `127.0.0.1:3085`), browser-demo, review-out.

## 7. Вопросы для консультации (ТЗ)

Мы хотим, чтобы платформа стала максимально стабильной и «супер-турбо» средой для
**лайв-кодинга + авторизованного пентеста/хакинга + реверс-инжиниринга**. Интересует честный,
независимый разбор — не «всё отлично», а конкретика: риски, слабые места, приоритеты.

### Q1. Стабильность
Где в такой архитектуре («всё — плагин» на Cordis, монорепо ~50 групп пакетов, Web GUI +
RPC + фоновые агенты + Chrome CDP) самые вероятные точки отказа, гонки, утечки контекста или
деградации сессии? Что укрепить в первую очередь, пока проект в rc и WIP?

### Q2. Архитектура
Топ-5 улучшений архитектуры, которые ты бы сделал: управление контекстом/памятью между
долгими сессиями, мультиагентная оркестрация, надёжность фоновых заданий, изоляция
песочниц/процессов, наблюдаемость (логи/телеметрия). Обоснуй кратко каждое.

### Q3. Система скиллов
У нас есть каталог скиллов + менеджер (CRUD, версии, бенчмарки, auto-improve). Как ты
организовал бы экосистему скиллов для power-user среды: метаданные/прогрессивное раскрытие,
зависимости между скиллами, конфликты, шеринг/установка скиллов, оценка качества?
Какие анти-паттерны скиллов ты видел у других платформ (Claude Code, Codex и т.п.)?

### Q4. «Супер-турбо» среда — что добавить
Представь идеальную среду для лайв-кодинга, пентеста и реверса на базе мульти-ИИ оркестра
(DeepSeek + внешние консультанты, Chrome CDP, локальные инструменты вроде IDA, Metasploit, Burp,
ghidra, сетевые сканеры). Что конкретно добавить: инструменты/интеграции, UI-механики,
автоматизации, безопасность engagement-режима? Назови 10–15 конкретных фич с приоритетами.

### Q5. Дорожная карта
Что бы ты внедрил первым (30/60/90 дней), чтобы максимально поднять стабильность и
эффективность при минимальном риске? Разбей по приоритетам.
