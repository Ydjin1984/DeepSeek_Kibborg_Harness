# 动作流与用户代码：设计规范

[English](2026-09-19-conversation-activity-design.md) | 中文

状态：设计方向「沉静记录」已选定，用于规划；实现将在计划确认后开始。日期：2026-09-19。

## 目标

「对话」「执行」「轨迹」三个标签页展示同一个会话，具有清晰的层级、可预测的详情展开，以及对最新动作的实时跟随。用户阅读较早的事件时，滚动不会被抢占。用户用三个反引号包裹的代码，在输入框和已发送消息中都能辨识。

## 数据来源与覆盖范围

- 「对话」与「执行」使用 Conversation Runtime 快照；「执行」对现有 Chat node 分组，并通过当前的 `conversation.chat.node` renderer 打开它们。关于工作进度的信息只来自已登记的事件、turn/step 与现有 plan/todo；界面不会杜撰阶段名称。
- 「轨迹」保留自己的记录注册表、表格、时间线与检查器。视觉上的一致性涉及层级、状态、链接与滚动，而不是合并数据模型。
- 用户的原始文本与附件不经转换即传给模型并被记录；标记只影响展示。
- 现有 Tool renderer 与 Host open-file 的公开操作保持不变。预览的来源是工具已经收到并展示过的结果。

## 「执行」动作流

- 顶部是紧凑的汇总，包含任务名称、状态、当前动作与计数器。其下是搜索与筛选。主区域是按时间顺序的记录，以细分隔线划分真实的用户轮次；只有在数据中存在可靠边界时才划分步骤。
- 每个动作有一行主行：类型、简短结果或目标、状态与时间/耗时。路径、命令和数值结果位于第二层。错误、等待确认与正在执行的动作无需展开即可区分。
- 详细输出、code/read/diff 卡片与调用链按需在同一位置通过现有 renderer 展开。搜索、筛选、全部展开、inspect 与跳转到文件始终保持可用。
- 读取记录中的文件名会打开它已记录的内联读取预览：行范围与行数、语言、高亮、复制。修改记录中的文件名会打开可用的 diff 或其他实际卡片。单独的「打开文件」动作使用 Host；如果历史中没有内容，界面不会创建虚构的预览。
- 滚动、焦点与行的展开不会改变事件的相对顺序。键盘与屏幕阅读器获得明确的标签、展开状态与可见焦点。

## 「对话」与「轨迹」

- 「对话」仍然是对话。辅助动作与文件链接获得相同的视觉层级和相同的展开规则；回答正文与用户消息仍是主体。
- 「轨迹」仍是用于核对步骤的详细记录。表格与时间线显示一致的状态标识，以及指向可用详情的跳转，同时保留虚拟化与精确元数据。
- 在同一会话内切换标签页时，每个标签页各自保留阅读位置与跟随选择。新会话打开时定位在最后一个可用的动作。

## 请求导航

- 在「对话」与「执行」滚动区域的右边缘，有一组窄的纵向短刻度，大致对齐可见记录高度的中点。它用于在真正已加载的用户请求与 steering（中途引导）消息之间导航，而不是额外的滚动条。
- 一个刻度对应一个请求。活动刻度显示当前正在阅读的区段所属的请求；跟随实时尾部时，活动刻度是最后一个请求。悬停或聚焦会显示编号与请求的开头片段，点击会跳转到它的消息。编号由已加载历史的顺序决定，在较早的页面尚未加载时不会被当作完整编号。
- 历史很长时，只同时显示活动请求附近数量受限的刻度窗口，并提供跳转到相邻区间的方式；界面不会创建成百上千个按钮。键盘获得清晰的标签与可见焦点。
- 跳转到较早的请求会把自动跟随切换到阅读模式。仅跳转到最后一个请求本身并不会开启跟随，直到用户到达底部或按下「跳至最新」。刻度不会遮挡文字、滚动条、悬浮按钮与输入框。
- 「轨迹」保留自己的 timeline 与 turn navigation；如果表格中需要同样的定位参照，它会使用表格现有的轮次边界，而不会叠加第二条 rail。

## 底部跟随

- 首次打开会话时，用户看到最后一个动作；跟随模式处于开启状态。
- 当用户有意用滚轮、触摸、键盘或拖动滚动条向上滚动时，跟随会立即关闭，即使离开底部的距离很小。该位置会在新事件到来、已展开卡片增高、加载较早历史以及窗口或输入框高度变化时保持不变。
- 当用户自己到达底部时，跟随会开启。「执行」标签页中现有的「跳至最新」按钮（类 `.jumpLatest`）会平滑地跳到末尾并开启跟随。各标签页中同类的现有控件保持相同的语义。
- 按下按钮后的跳转平滑而短暂；任何手动干预都会中断这次跳转。在 `prefers-reduced-motion` 下，跳转瞬时完成。流式输出期间，底部会持续贴底，不会排队重复的 smooth 动画：新行或当前行的增高会把旧内容上移，最后一个动作始终留在画面内。
- 程序化修改 `scrollTop`、几何误差、ResizeObserver 与切换标签页都不算作用户手势，本身不会开启跟随。

## 用户文本中的代码

- 由三个反引号组成的行开启和关闭围栏代码块；开启反引号之后允许带可选的语言名，例如 `ts`。支持多个代码块，以及它们之前、之间和之后的普通文本。
- 输入框中可见可区分的代码边界与背景，而不替换原生 textarea：选区、IME、粘贴、撤销、换行、高度与光标都照旧工作。输入期间代码块未闭合时，样式会延续到草稿末尾。
- 已发送的用户消息中显示独立的代码卡片，保留空格、换行与复制按钮；标明的语言会启用现有高亮，未知语言会安全地按文本显示。
- `@` 引用与 claim token 只在围栏代码块之外处理；在代码内部它们保持为字面字符。用户消息的其余部分仍是带现有引用的纯文本，不使用任意 HTML。
- 长代码不会为每个字符创建交互元素；草稿样式按片段重新计算，而不是按每个字符。

## 验收标准

- 在真实的短会话与长会话上，记录保持顺序、搜索、筛选、展开、inspect、文件链接、ReadBlock/DiffBlock 与错误。
- 三个标签页都通过以下场景：首次打开；流式新增记录；最后一条记录增高；向上移动几个像素；等待新事件；手动回到底部；点击「跳至最新」；中断跳转；切换标签页；加载较早历史；输入框高度变化。
- 「对话」与「执行」中的导航刻度与滚动保持同步，在 prepend 与筛选之后跳转到正确的请求，可由键盘操作，并且即使有数百个请求，元素数量也不超过受限的窗口。
- 在 5000 个事件的集合上，「执行」已挂载的行数受窗口与 overscan 限制（典型窗口高度下的目标上限为 120）；已展开的行与按搜索跳转仍然可用。修改前后都会保留用于挂载、流式更新、滚动与输入的浏览器 profile。
- 在目标机器上，预热之后流式更新不会产生超过 50 ms 的长帧；帧 p95 的基准是 16.7 ms。如果实测未达到基准，执行计划会记录原因，并在验收前消除它。
- 任何模型行，包括围栏代码与附件，都不会因为样式而在记录或模型请求中发生变化。
